Cleaning, Chunking, and Token Estimates

Retrieval quality begins before indexing. A deterministic content pipeline removes page furniture, preserves technical structure, and produces chunks whose identity does not depend on process-randomized hashes.

Content cleaning

ContentProcessor removes scripts, styles, templates, noscript blocks, and clearly identified navigation or footer regions. Cleaning remains conservative: an unfamiliar element is kept when it contains useful visible text. Unicode is normalized without transliterating identifiers or changing code.

  • Discard executable and hidden page furniture.
  • Keep article prose, tables, lists, and code samples.
  • Resolve useful links against the effective response URL.

The processor emits normalized plain text and minimal Markdown from the same structured blocks.

Structure preservation

Heading paths capture the active H1 through H6 hierarchy for each block. Nested lists retain item order and indentation. Preformatted code remains a distinct block so whitespace-sensitive examples are not merged into prose. Simple tables preserve header and row relationships.

for block in blocks:
    emit(block.heading_path, block.kind, block.text)

A same-origin canonical URL may be recorded as source identity. A cross-origin canonical link is ignored for identity to prevent a page from claiming another site’s document key.

Heading-aware chunks

TextChunker groups adjacent blocks under their heading path toward target_chars=1200, enforces max_chars=1600, and carries up to overlap_chars=160 into the next chunk. Boundaries prefer paragraphs and list items over arbitrary character positions.

Very large prose or code blocks are split deterministically. Empty and heading-only chunks are discarded. Chunk IDs use SHA-256 over stable source and content fields, so identical input produces identical identities across processes.

Heuristic token estimate

HeuristicTokenEstimator uses ceil(character_count / 4). This estimate is fast, local, and model-agnostic, but it is not exact tokenization. Dense code, non-Latin text, and unusual whitespace may differ from a particular model tokenizer.

estimated_tokens = max(1, math.ceil(len(text) / 4))

The same estimator must be used for indexed totals and selected context so reduction metrics are internally consistent. Reports should always label the number as estimated tokens.
