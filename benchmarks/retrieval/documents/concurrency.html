Bounded Concurrency and Cancellation

Crawl throughput comes from overlapping independent waits, but every layer still needs a finite capacity. Bounded concurrency protects file descriptors, remote origins, memory, and cancellation latency.

Semaphore hierarchy

SemaphoreManager combines a global semaphore with per-domain semaphores. A task must hold both capacities before issuing a network request. The order is stable for every task so that two requests do not acquire the same locks in opposite order.

async with semaphore_manager.limit(url):
    response = await request(url)

Hostname keys are canonicalized before lookup: case, trailing dots, Unicode IDNA spelling, and default ports must not create independent domain buckets. Inactive per-domain limiters can be removed only when no task owns or waits on them.

Rolling scheduler

A rolling scheduler fills a fixed worker window, waits with asyncio.FIRST_COMPLETED, processes completed tasks, and then refills the window. It does not materialize one task for every discovered URL. Therefore a million queued links do not become a million live task objects.

done, pending = await asyncio.wait(
    active,
    return_when=asyncio.FIRST_COMPLETED,
)

Refill occurs after results enqueue newly discovered links. The active set and queue size are separate limits: one bounds executing work and the other bounds retained future work.

Cancellation cleanup

When the parent crawl is cancelled, it first cancels active child tasks, then awaits them with exceptions collected, and finally closes owned network resources. Awaiting cancelled children is required; merely calling task.cancel() can leave response contexts and semaphore permits pending.

for task in active:
    task.cancel()
await asyncio.gather(*active, return_exceptions=True)
raise

Cleanup should be shielded only for the smallest indispensable release operation. Broad shielding makes a cancelled crawl continue doing useful work after its caller has left.

Queue state transitions

CrawlerQueue tracks a URL through explicit states such as queued, in progress, completed, failed, or deferred. Deduplication happens before enqueue, while a retry or politeness delay may defer an already known item without pretending it completed.

  • Only a queued item can become in progress.
  • A completed identity is not scheduled again.
  • Cancellation returns unfinished ownership to a recoverable state.

Priority and FIFO sequence numbers make ties deterministic. Queue statistics should derive from these transitions rather than from unrelated task callbacks.
