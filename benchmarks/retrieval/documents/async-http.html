Async HTTP Timeouts and Lifecycle

An asynchronous crawler needs explicit ownership rules for clocks, connections, responses, and shutdown. Fast requests are not enough: the client must remain bounded when a peer accepts a connection and then stops sending bytes.

Timeout budgets

A connect timeout limits DNS resolution and connection establishment. A read timeout limits inactivity while response bytes are expected. They are different from a whole-operation deadline, which also includes robots policy, rate slots, redirects, and retry backoff. A useful timeout budget allocates time to each phase instead of restarting an unlimited clock after every retry.

  • connect_timeout protects connection setup.
  • read_timeout detects a stalled response stream.
  • An outer deadline bounds the complete logical fetch.
async with asyncio.timeout(operation_timeout):
    body = await crawler.fetch(url)

Cancellation from the outer deadline must be re-raised after cleanup; it is not a transient network result.

Session lifecycle

AsyncCrawler lazily creates one pooled client session and shares its connector across fetches. Reusing the session preserves connection pooling and gives concurrency limits one clear owner. Creating a session per URL wastes sockets and makes shutdown races more likely.

async with AsyncCrawler(config) as crawler:
    pages = await crawler.fetch_multiple(urls)
# __aexit__ awaits close()

close() should be idempotent. A second call must not close a replacement session or fail because the first caller already released the connector. Lifecycle logs belong on a diagnostic channel, never mixed with machine-readable results.

Response ownership

The coroutine that opens a response owns its body and release path. Reading, decoding, and status classification happen before the response context exits. If parsing is moved to a worker task, copy the required body and metadata first; do not pass a live socket-backed response beyond its context manager.

  • Consume or release every response.
  • Preserve the final response URL for relative-link resolution.
  • Keep the requested URL separately for result identity and audit.

This ownership rule also applies to redirect hops and robots.txt requests. Every early return needs the same cleanup as the successful branch.

Empty bodies and failures

A compatibility-oriented fetch() interface may return the empty string for both a successful zero-length body and a handled request failure. That ambiguity is intentional when the public return type must remain str. Callers that need the distinction should use structured crawl statistics or an error-aware internal result.

text = await crawler.fetch(url)
if text == "":
    # Empty response body or failed fetch; consult diagnostics.
    pass

Do not convert cancellation into an empty string. Cancellation controls task lifecycle, while an empty return value represents an ordinary completed call under the compatibility contract.
