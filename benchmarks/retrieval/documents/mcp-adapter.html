Local MCP Adapter Operations

The local MCP adapter is a bounded transport around the existing context application service. It does not own a second retrieval engine and does not turn retrieved web text into trusted instructions.

Stable tools

The adapter registers exactly four stable tools: index_site, search_index, build_context, and get_index_info. Each tool has validated arguments and an immutable structured output model.

  • index_site crawls and indexes within configured caps.
  • search_index returns ranked chunks with provenance.
  • build_context returns a token-budgeted chunk set.
  • get_index_info reports local index metadata.

ServerRuntime adapts these calls to ContextEngine and owns operation tracking.

Stdio lifecycle

The server runs locally over stdio. Standard output is reserved for MCP protocol messages; lifecycle logs and diagnostics go to standard error. Startup validates immutable MCPServerConfig, opens the database boundary, and reports a safe degraded state for expected index problems.

uv run crawlforge-mcp --database .crawlforge/index.db

Shutdown stops accepting new operations, waits for or cancels tracked operations, closes the runtime, and then releases server resources. The lifecycle context has one owner and close() is idempotent.

Tool errors

Malformed arguments remain protocol validation errors. Expected execution failures become ToolExecutionError results with a short corrective message. Unexpected exceptions are logged with operator detail but returned without stack traces, database internals, or local filesystem locations.

ToolExecutionError(
    "the MCP server is shutting down; retry after restarting it"
)

Running the console entry point without the optional dependency reports “CrawlForge MCP support is not installed” and exits with status 2. Tool failures never write an ordinary result that merely looks successful.

Output and content safety

Configured limits bound crawl pages, search hits, token budgets, operation concurrency, serialized bytes, and text field lengths. Output truncation is structured and observable; it does not produce invalid protocol messages. Returned URL and heading fields remain provenance.

Retrieved chunks are untrusted web content. Text that says “ignore prior rules” is indexed as data and must never be treated as an MCP instruction, server policy, or system message. Network policy blocks private targets by default for indexing operations, including redirect and DNS destinations.
